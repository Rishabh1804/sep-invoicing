The owner, 17 Nov 2026: *"a bug sweep — some bugs that I've encountered is mostly based on navigation when entering data,
creating a new invoice which still doesn't have keyboard navigation. Fix all the non load bearing bug fixes"*, then a second
round: text overflowing or hugging its box; focus slips and the page not orienting on a challan of three or more lines by
keyboard; the Backspace bug; general bugs and data leaks; dead code, privacy leaks and prompt injection. Eight agents, each on
its own copy, each fix with a spec that fails on the build before it. **All merged in #203** (`b55c8cd`), CI green on both halves.

**Load-bearing** meant: arithmetic, what is saved or validated, invoice numbers and voids, the guard, persistence and `S`, sync,
export and backup, credentials, prompt wording, git history. Those were reported to the owner, never fixed in the sweep. What he
ruled is in the last section; the security findings are kept in the private codex, not here (the repository is public).

**How each row reads**: *where* · what the owner met · the cause · the resolution · the spec · the topic that now holds the rule.

## The process, as it went
- Two agents' copies began on a stale commit (#189); their work was cherry-picked onto the branch and re-run there. Agents now
  `git reset --hard` to the branch head first and check `git log -1`.
- Several Playwright servers on one machine: `reuseExistingServer` silently used another copy's build. Each run took its own
  `PW_PORT`.
- A rebuild under a running suite changes the page it serves: three failures in the full run were that, and passed on re-run.
- Each push to the pull request cancelled the CI run before it; the last fixes were held until a run finished.
