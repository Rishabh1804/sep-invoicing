## Findings

### The keyboard problem was mostly not the dropdowns
The obvious half was real: both suggestion surfaces — part autocomplete and client search —
rendered with no way in but a click, and the `keydown` handler explicitly **returned early on
Enter** whenever a list was open, so the one key a user would try did nothing at all.

The quieter half mattered more. `renderAddChallanForm()` rebuilds the form by replacing
`innerHTML`, which destroys the focused element and drops focus to `<body>`. Every structural
change — adding a line, changing a unit, picking a client — silently ended the keyboard path
and forced a mouse click back in. Fixing the dropdowns alone would have left entry still
requiring a pointer every second or third field.

The fix is a `data-k` key on every control, captured before the re-render and restored after,
with callers able to name a better destination (picking a part hands focus to that line's
quantity; adding a line focuses the new part field). **Focus is restored last in the render**,
after the client-search auto-focus, so nothing above can steal it back.

`data-kbd-ring` puts the Add Line and Save buttons into the Enter chain so the last field of
the last line steps onto "Add Line Item" instead of dead-ending. A line's remove `×` is
deliberately excluded — that chain is walked by repeated Enter presses, and a destructive
button in it is a data-loss bug waiting for a distracted operator.

### The app was very likely not installable at all
`manifest.json` declared **no `icons` array**. Both PNGs shipped, both were cached by the
service worker, and `apple-touch-icon` pointed at one — but the manifest itself never
mentioned them, and an icon in the manifest is Chrome's floor for offering "Install app". The
PWA has probably not been installable on Android for as long as that file has existed.

Also added: `maskable` purpose (without it Android letterboxes the icon in a white circle),
`description`, `scope`, `display_override`, and two app shortcuts.

**`id` was deliberately left out.** Setting it would be good practice on a new app, but
relative-`id` resolution differs between the spec text and shipped implementations, and
getting it wrong changes an installed app's identity — orphaning the existing install as a
duplicate. The default identity is `start_url`, which is exactly today's behaviour.

### One CDN hiccup could stop the worker activating
`install` put the Google Fonts stylesheet in the same `cache.addAll()` as the local assets.
`addAll` is atomic: a single failure reaching `fonts.googleapis.com` rejected the whole
install, so the worker never activated and **nothing** was cached — including the local icons
that would have succeeded. Core same-origin assets are still atomic; the font is now
best-effort and swallows its own failure.

Related: only the font *stylesheet* was ever cached, never the woff2 files it points at, so an
installed app went offline and lost its typography anyway. Font hosts are now runtime-cached.

## The Canon 0034 Amendment — worth your attention

Canon 0034 (global) reads: *service workers never cache HTML.* You asked for an offline layer,
which cannot be built while abstaining from the app shell, so the canon is now honoured by a
different mechanism rather than by abstention.

Navigations are **network-first**. An online device always renders the HTML the server just
sent; the cached shell is consulted **only after `fetch` has actually thrown**. The failure
mode the canon exists to prevent — a stale shell served forever to a device that stops asking
the network — cannot form, because the cache is never *preferred* while the network answers.

This is a real change to a cross-repo rule and Codex/SproutLab were not touched. If you want
the canon restated globally rather than carved out for SEP, that is a decision for the Consul.

## GitHub Sync — the design decisions

**It is last-writer-wins, and that is deliberate.** The state is a single document with no
per-record clocks or vector versions. Anything other than last-writer-wins would be inventing
a reconciliation the app cannot verify, and inventing one silently on GST filing records is
worse than not having one.

**No overwrite is blind.** Each device stores the blob SHA it last exchanged. Before a push,
the current remote SHA is read; if it has moved, another device wrote in between and you are
told whose copy and when, with counts, before anything is replaced. Auto-push refuses outright
in that situation rather than prompting a screen nobody is looking at.

**Auto-push is opt-in and debounced ~45 s.** `saveState()` fires on keystroke-driven
recalculation; pushing per save would be both useless and rate-limited. One failure sets a
backoff so a broken config cannot re-arm a timer forever in the background.

**Credentials.** The token lives in `sep_inv_github_token`, and the sync config in
`sep_inv_github_sync` — both off the state object, so a JSON export can never carry either.
There is a test asserting the exported file does not contain the token. The sync config is
kept off `S` for a second reason: a file SHA and device id describe *this* device's
relationship to the remote, and restoring someone else's backup must not hand this device
their sync position.

**The security posture is honest but not strong.** A PAT in localStorage is readable by
anything that can run script on the origin, and by anyone holding the unlocked device. Use a
**fine-grained token, Contents: Read and write, one private repo, nothing wider** — the
Settings copy says exactly this. If a device is lost, revoke the token; the data on it is
already exposed regardless.

## Stats — one behaviour change to know about

**Periods now filter on the invoice date, not `createdAt`.** An invoice dated 31 July and
entered on 2 August used to land in August. It is now July — the date on the document, the
date GSTR-1 reports it under, and the date a customer quotes back. `createdAt` remains the
fallback for rows carrying no date. This shifts numbers you may have seen before; it shifts
them toward being correct.

That change broke one existing test, and the break was informative rather than incidental.
`p4-revenue-empty-state` seeded an invoice dated `2026-04-15` with `createdAt: Date.now()` and
asserted that the empty state was absent. It only ever passed because the filter read
`createdAt` and ignored the date entirely — the same class of fixture time bomb the last
session found in `invoice-send` and `payment-record`. Repaired the same way, with `todayIso()`.

The rework also dropped the grand-total figure from the revenue card, which `golden-flows`
caught. That was my regression, not a stale test: "information is missing" was the brief, so
losing a number is the wrong direction. It is back, as the incl-GST sub-line on the revenue
tile.

**Tonnage states its own coverage.** It comes from KG lines directly and from NOS lines via
`partWeights` or Items Master `stdWeightKg`. Where a part has no weight, the line cannot be
counted — so the card says what percentage of lines it covered. An uncovered line understates
tonnage and therefore *overstates* realisation, which is the direction that flatters, so it is
called out rather than left to be discovered.

The Items Master weights recovered as `pieceRate ÷ ratePerKg` are used here without apology:
such a weight prices back at exactly that rate and so can never rank a part by margin, but it
measures tonnage correctly, and tonnage is all it is asked for.

**Realisation by client is sorted worst-priced first.** That ordering is the entire point of
the table — the largest account and the worst-priced one can be the same row.

## `defaultCostPerKg` — please check this

The default for a **fresh install** moved from ₹5.46 to ₹8.55, matching the Apr–Jul 2026
rebuild. An existing configured value is never overwritten, by design.

**Your live value is almost certainly still ₹5.46**, and last session's handoff flagged it
unresolved. Everything new in Stats measures against it — realisation, margin, the below-cost
alert, and which clients appear in red. At 5.46 the dashboard will report a comfortable margin
on work that is actually near break-even. **Settings → Cost of Goods → set it to 8.55.**
